# 国策设计工作区

这里是新国策的唯一设计入口，回答“准备建立什么长期规则，以及怎样先验证再固化”。所有方案文件直接放在本目录，不再建立“草稿、待审、试行”等多层子文件夹；阶段变化写进文件状态栏。

## 与相邻目录的区别

| 内容 | 应放位置 |
|---|---|
| 新长期国策、制度改版或废止提案 | 本目录 |
| 过去已经采用或执行过的专项方案 | `../03_已执行方案/` |
| 某一年或若干季度的资源优先顺序 | `../02_战略方针/` |
| 本季度责任人、额度、期限和验收任务 | `../../01_季度政务/04_执行任务/` |
| 玩家教训、偏好和未成形想法 | `../05_玩家笔记/` |
| 已正式确认仍长期有效的制度 | `../01_制度规则/关键制度源头/01_长期国策有效清单.md` |

## 文件命名

统一使用：`GP-三位编号_国策名称.md`，例如 `GP-001_常平仓储备与灾害兜底制度.md`。编号只表示档案顺序，不表示已经批准。

## 文件内状态

只使用以下状态，并直接更新同一份文件：

`待整理 → 待密谈 → 试行设计 → 已下诏 → 待反馈 → 续试／转正／终止`

“已下诏”只属于 L2 命令；“转正”为长期国策前，必须有玩家明确确认，并能链接到正式诏书和游戏反馈。没有 L3 结果，不得写“已完成”。

## 一项国策必须写清

1. 编号、拟定季度、状态和提出原因。
2. 要解决的问题、当前实际基线和资料来源。
3. 与现有长期国策、战略方针和当季任务的关系，注明继承、修订、冲突或互不影响。
4. 制度机制、适用地区和对象、负责人、协同机构、钱粮来源、监督和退出条件。
5. 若先试行：试行季度、地区、预算、实得目标和复核节点。
6. 数值分层：实际基线、御前实得目标、预计执行系数、诏书底线、上考、失败线。
7. 风险、禁区、失败后的止损办法和到期处理。
8. 证据链接：密谈、正式诏书、执行任务、季度纪要和当前状态分别链接，不复制冒充。

可直接复制项目 Skill 的模板：`../../../skills/design-imperial-policy/assets/国策方案模板.md`。使用 Codex 时可明确调用 `$design-imperial-policy`。

## 归档门槛

- 仍在构思：留在本目录，状态为“待整理”或“待密谈”。
- 已决定本季试行：本目录保留制度设计，同时将本季可执行部分拆到季度执行任务；两者互相链接。
- 已正式下诏：补充诏书路径，状态改为“已下诏”或“待反馈”，不预写结果。
- 已收到反馈：补充 L3 结果和偏差；由玩家决定续试、转正或终止。
- 转为长期国策：在长期国策有效清单登记正式生效依据，本设计稿仍保留，不覆盖历史。
