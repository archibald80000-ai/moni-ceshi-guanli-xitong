# 《历史模拟器：崇祯》核心循环与参数档案

> 用户口述的“重整模拟器”按实际游戏名称统一为《历史模拟器：崇祯》。  
> 本文件只整理公开机制和本项目需要保存的数据，不提供自动代玩。

## 一、公开机制结论

《历史模拟器：崇祯》以自然语言诏书驱动世界模型，没有固定的A/B选项；游戏中的状态反馈和大臣对话由大语言模型实时生成。官方对自接API的说明进一步表明，推演模型负责理解诏书、结合国情推理连锁反应，并把结果转化为具体数值与状态变化。因此，档案系统不能只保存诏书，还必须同时保存下诏前的上下文和下一季度实际反馈。

官方更新还说明，主动存档会保存本回合推演前的大臣对话和快捷操作，并持续修正长期记忆写入。这说明“本季度密谈”和“当前状态快照”都属于关键输入，不能只保留最终诏书。

公开玩法资料显示，游戏包含标准、灾情、民心、动乱、城防、税收等地图视图，玩家通常先看局势、召集大臣议政、下达自然语言诏书，再由AI推演结果。

## 二、本项目采用的季度循环

```text
进入春／夏／秋／冬
  → 游戏报告上一季度结果
  → 归档朝政纪要并刷新国家底账
  → 召集大臣密谈，保存话术与各方意见
  → 玩家确定战略
  → AI按玩家要求起草诏书
  → 玩家审核并提交游戏
  → 登记执行任务和验收指标
  → 游戏世界模型推演
  → 进入下一季度并取得新报告
```

## 三、必须保存的核心参数

### 1. 回合与证据

- 年号、年份、季节；
- 当前阶段：刚收到反馈／密谈中／已下诏／执行中／已结算；
- 上一季度纪要、当季密谈、当季诏书、下一季度反馈；
- 资料来源、截图、更新时间和证据等级。

### 2. 皇帝与朝廷

- 皇帝威望或权威、健康及其他面板状态；
- 官员姓名、官职、身份、派系、立场、影响力、能力、状态；
- 提名、钦定、交印、到任、履职、离任、死亡；
- 兼差、与皇帝关系、考成、赏罚和历史事件；
- 各阶层、党派满意度与腐败。

### 3. 财政与产业

- 国库、内帑、专项资金、企业股本；
- 季度收入、支出、净结余；
- 田赋、盐课、市舶、商税、矿课及其他税收；
- 产能、实际产量、库存、拨出、到达、销售、实收、净收益；
- 工程预算、实支、完工率、使用率和维护成本。

### 4. 军队与装备

- 军队名称、主官、势力、驻地、编制定额与实到；
- 战兵、辅兵、侦骑、水师等分类；
- 经验、士气、忠诚、补给、训练、可战、可调；
- 冷兵器、火铳、燧发枪、盔甲、红夷炮、轻型火炮、战马；
- 库存、季度产量、拨付、到营、可用、在修、报废和缺口；
- 船型、战船数量、维护费和水军人数。

### 5. 地方与人口

- 两京十三省、辽东及其他地块；
- 总人口、民心、动乱、灾害、城防、税收；
- 田赋收入、田亩、屯田、实耕、粮仓和粮价；
- 巡抚、总督、总兵、都指挥使；
- 疫情、死亡、流民、叛军和地方军力。

### 6. 外交、势力与情报

- 后金／大清、蒙古诸部、朝鲜、海商与欧洲势力；
- 统治者、民心、人口、仓廪、权威、通货供应和控制地块；
- 外交协议、互市、港口、护航、订单、实收；
- 情报来源、时间、内容、等级、有效期和双源复核。

### 7. 政令和长期战略

- 政策目标、执行对象、钱粮兵额、期限、奖惩；
- 实际基线、御前目标、预计执行系数、诏书底线、上考、失败线；
- 计划状态、前置依赖、负责人、对应诏书和季度结果；
- 国策、常设制度、临时机构及其成立、续办和退出条件。

## 四、档案设计原则

1. 一季度至少保存“密谈话术、正式诏书、朝政纪要”三件套。
2. 诏书是输入，季度纪要是结果，两者不得合并成一个文件。
3. 同一数字必须标注它是目标、预算、产能、库存、在途还是实际结果。
4. 当前状态只由最新反馈刷新；历史计划不得反向覆盖当前事实。
5. 公开攻略所称“第一行优先识别”等经验可作为写作提示，但未见官方硬规则时不得当作底层接口保证。
