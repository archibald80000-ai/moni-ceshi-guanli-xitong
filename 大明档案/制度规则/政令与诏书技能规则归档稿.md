~~~markdown
# writeimperial-causal-ledger

## 一、技能目的

本技能不是单纯替皇帝下命令，而是向历史模拟系统提交一份完整的项目因果证明。

一项政策要被系统承认，必须证明：

1. 世界中已经存在足够的资源；
2. 朝廷已经建立能够控制这些资源的组织；
3. 项目拥有明确的人员、设备、资金和生产方法；
4. 每个执行环节能够产生可计算的中间结果；
5. 中间结果能够转化为最终产量、收入、军力或民心变化；
6. 最终收益能够由前文数字计算得出，而不是在结尾凭空宣布。

强制逻辑链：

`资源基础 → 管理组织 → 生产方法 → 人员与投入 → 实际产出 → 销售或使用 → 成本扣除 → 收益分配 → 监督验收 → 最终面板结果`

核心铁律：

> 政令末尾的每一个收益数字，都必须能够沿正文逐级倒查到资源、单位产出、价格、损耗和成本。

任何无法倒查来源的数字，均视为“孤立收益数字”，不得写入正式政令。

# 二、诏书与政令的层级

## 1. 诏书

诏书是一个季度的国家总文件，固定包含：

- 总序；
- 【军事】；
- 【内政】；
- 【外交】；
- 【其他】；
- 钦此。

完整诏书只在开头使用一次：

`奉天承运皇帝，诏曰：`

只在末尾使用一次：

`钦此。`

## 2. 政令

政令是四大部分内部的一项完整项目。

一项完整事业通常对应一条政令。例如：

- 皇庄统一经营；
- 官银局通存通兑；
- 盐引制度改革；
- 登莱军工厂扩建；
- 辽东敌后破袭；
- 全国水利复耕；
- 三军军械列装。

政令内部可以有“一、二、三……”若干执行条款，但这些条款不是独立政令，而是同一个项目不可分割的执行链。

# 三、政令强制三段式

每条政令必须使用以下三段结构。

## 第一段：世界状态与项目总纲

第一段负责证明项目为什么能够成立。

必须交代：

- 现有资源总量；
- 实际可投入数量；
- 当前问题；
- 项目归属；
- 总负责人；
- 协同和监督机关；
- 资金、粮食、设备或人员来源；
- 项目的总目标。

第一段不得只写空泛背景。

错误：

`皇田众多，经营不善，着王承恩整顿。`

正确：

`查没阉党田产380万亩，并入原皇田1551万5200亩，合计1931万5200亩，其中扣除道路、水渠、庄舍、轮休及争议田181万5200亩，实际经营土地1750万亩，悉归大明皇庄司统管，直隶内务府。王承恩总办，户部核成本与收入，锦衣卫核田籍和物资，都察院季末抽验。`

第一段回答：

- 有多少资源；
- 多少资源真正可用；
- 资源由谁控制；
- 账由谁核；
- 项目从什么基线开始。

---

## 第二段：编号列明完整执行链

编号条款共同完成一个项目，不分别结算最终收益。

推荐结构：

一、组织与管理。  
二、生产或行动布局。  
三、人员、劳力与投入。  
四、原有人员和利益关系处理。  
五、地方权限、安全及风险边界。  
六、技术、市场和推广方式。  
七、销售、入库和收益分配。  
八、监督、账册和处罚。

编号数量不是固定的，可根据项目使用3至9条。

每一条必须尽可能包含数字，不得只有抽象方法。

错误：

`统一购买农具和耕牛，提高生产效率。`

正确：

`统一采购制式农具60万副，调集耕牛8万头，按每头每季饲料、兽医和折旧3两计支24万两；另备种粮20万石，按每石8钱计支16万两。农具、耕牛、种粮逐庄登记，实际到庄率不得低于95%。`

编号条款必须建立中间数据，使最终结果可以计算。

---

## 第三段：统一结算综合结果

所有执行办法写完后，统一结算整个项目。

必须依次写：

1. 实际经营或使用规模；
2. 单位产出；
3. 总产出；
4. 合格率、损耗率或留用比例；
5. 可销售、可入库或可列装数量；
6. 成交价格或折算价值；
7. 总收入或总军事成果；
8. 各项成本；
9. 净收益或净效果；
10. 收益分配；
11. 就业、民心、军力、风险等附带结果；
12. 必须更新的面板。

正式政令中不得使用：

- 预计能够；
- 有望提高；
- 将逐步形成；
- 可能增加；
- 待下季度观察。

应使用确定式表达：

- 经此施行，形成；
- 本季取得；
- 实际达到；
- 由此增加；
- 由此下降；
- 净得；
- 足以使；
- 季末定为。

政令中的确定式结果属于“政策推演结论”。在数据库中仍须与后续朝政纪要确认的“实际结果”分开保存。

```text
资源总量：
保留、争议、不可用数量：
实际投入数量：

单位投入：
单位产出：
总产出：

合格率：
损耗率：
留用数量：
可出售、可入库或可列装数量：

成交单价或折算价值：
总收入：

原料成本：
人工成本：
设备成本：
折旧维修：
运输仓储：
管理审计：

总成本：

净收益 = 总收入 - 总成本

~~~

没有这些字段时，不得直接写净收入。

# 五、收益数字倒查规则

政令结尾中的所有数字必须有上游来源。

例如结尾写：

```
皇庄每季净收入260万两。
```

正文必须能够倒查：

```text
实际经营土地：1750万亩

其中：
高产作物1200万亩
普通粮作550万亩

高产作物每亩可售余粮：0.45石
普通粮作每亩可售余粮：0.29石

高产作物可售粮：
1200万亩 × 0.45石 = 540万石

普通粮作可售粮：
550万亩 × 0.29石 = 159.5万石

合计可售粮：
699.5万石

平均成交价：
每石0.8两

营业收入：
699.5万石 × 0.8两 = 559.6万两

本季总成本：
300万两

净收益：
559.6万两 - 300万两 = 259.6万两

考成取整：
260万两
```

如果无法建立这条算术链，就不得写260万两。

# 六、成本不得缺项

农业与皇庄项目至少考虑：

- 种子；
- 农具；
- 耕牛购置或折旧；
- 耕牛饲料和兽医；
- 雇工工资；
- 雇工口粮；
- 水利；
- 道路；
- 仓储；
- 运输；
- 管理人员；
- 审计；
- 损耗；
- 留种；
- 自用粮。

军工项目至少考虑：

- 原矿、铁料、木料和火药原料；
- 工匠工资；
- 厂房和设备；
- 燃料；
- 废品率；
- 返修；
- 试射；
- 炮车、弹药和配套人员；
- 运输；
- 军团实训。

商贸项目至少考虑：

- 货物采购；
- 包装；
- 仓储；
- 船运或陆运；
- 护航；
- 损耗；
- 关税；
- 商户佣金；
- 坏账；
- 退货；
- 实际到账。

只写收入、不扣成本，视为逻辑不闭环。

------

# 七、产量不得直接等于收益

必须区分：

- 土地面积；
- 实播面积；
- 收获产量；
- 留种和自用；
- 商品数量；
- 实际成交；
- 银两到账；
- 扣除成本后的净收益。

禁止写法：

```
种植1200万亩高产作物，因此收入260万两。
```

正确链路：

```
1200万亩 × 单位可售余粮 → 高产作物商品粮；加上其他作物商品粮 → 总商品粮；总商品粮 × 实际成交价 → 营业收入；营业收入 - 全部成本 → 净收益。
```

同理：

- 库存不是列装；
- 产能不是产量；
- 产品出厂不是销售；
- 合同不是收入；
- 拨款不是成本；
- 战果申报不是核实战果；
- 建筑完工不是建筑收益；
- 学员入学不是人才到岗。

------

# 八、非银两收益也必须有计算依据

## 1. 就业

不能只写“吸纳大量流民”。

必须说明：

- 项目需要多少工日；
- 每名雇工每季工作多少日；
- 总工日可以容纳多少人；
- 工钱与口粮支出是否已列成本。

例如：

```text
本季总需工日：3600万工日
每名雇工工作90日
稳定雇工：3600万 ÷ 90 = 40万人
```

因此才能写：

```
皇庄稳定吸纳流民、无地农户及原佃户40万人。
```

## 2. 民心和满意度

必须由可见利益支持：

- 工资到账；
- 粮价下降；
- 获得土地；
- 免税；
- 水利受益；
- 安置留存；
- 扰民减少。

普通季度变化通常为1至2点。大型全国项目、投入巨大且受益广泛时，方可写2至5点，并说明受益人口比例。

## 3. 动乱风险

必须由以下数据支撑：

- 无业流民减少；
- 粮价下降；
- 赈济到账；
- 土地纠纷减少；
- 地方武装活动减少；
- 军队扰民减少。

不得因为修建一个工厂，就无依据地令全国动乱下降10点。

## 4. 军事经验、士气和补给

必须由以下因素支持：

- 实战参与人数；
- 训练人次；
- 伤亡和归队；
- 军饷到账；
- 军械到营；
- 粮弹供给；
- 战果规模。

------

# 九、项目何时另立政令

同一个完整经营闭环不得过度拆分。

只有符合以下一项以上，才另立政令：

1. 已经属于另一个独立项目；
2. 总负责人完全不同；
3. 使用另一笔独立专款；
4. 拥有独立技术和产出；
5. 即使原项目不执行，它仍能单独成立；
6. 最终结果进入另一套核心面板。

例如：

皇庄的土地登记、集中耕种、流民雇佣、水利共享、良种推广和利润分配，属于同一经营闭环，应写在一条皇庄政令内。

但以下应另立政令：

- 官银局；
- 盐引司；
- 矿业改造；
- 军械厂扩建；
- 辽东破袭；
- 武备学堂；
- 漕运整顿。

# 十、正式政令模板

```text
【项目名称】

今有[资源总量]，其中[保留、争议或不可用数量]，[实际可投入数量]归[正式机构]统一管理。现因[具体问题]，着[总负责人]总办，[协同机关]会办，[监察机关]核验，拨用[资金、粮食、设备、人员]，统一施行。

一、[组织管理方式，包括机构、人员、覆盖范围和数量]。
二、[生产布局，包括投入规模、单位产出和总产出]。
三、[人力投入，包括人数、工日、工资、口粮和成本]。
四、[原有人员、利益关系与安置办法]。
五、[地方边界、安全边界、停止线和禁止事项]。
六、[技术推广、市场销售、运输仓储或实际使用办法]。
七、[总收入、成本构成、净收益及分配办法]。
八、[账册、审计、证据、面板和处罚办法]。

经此施行，[实际投入规模]形成[总产出]；扣除[留种、自用、损耗]后，[可销售或可使用数量]按[单价或价值]取得总收入[数字]。种子、原料、人工、设备、运输、仓储、维修和管理共支[数字]，净得[数字]。其中[分配比例及金额]。项目同时吸纳[就业人数]，使[产能、收入、粮价、满意度、军力、风险等]发生[明确变化]。季末以[最终数值]及[指定面板]同步更新为验收；无实数、无原始凭证、账实不符或面板未更新者，按未完成论。
```

# 十一、皇庄项目示例

```text
【大明皇庄统一经营令】

查没阉党田产380万亩，并入原皇田1551万5200亩，合计1931万5200亩；扣除道路、水渠、庄舍、轮休及争议田181万5200亩，实际经营土地1750万亩，悉归大明皇庄司统管，直隶内务府。王承恩总办，户部核成本收入，锦衣卫核田籍物资，都察院季末抽验。

一、皇庄按地区设场长、农技员、账房，稳定雇工40万人，每人每日工钱5分、口粮2斤，每季工作90日，工资共支180万两，口粮60万石折银48万两。二、统一采购种粮20万石，支银16万两；农具60万副，采购维修支银18万两；调集耕牛8万头，饲料、兽医及折旧每头3两，共支24万两。三、1200万亩种番薯、玉米，每亩形成可售余粮0.45石；550万亩种传统粮作，每亩形成可售余粮0.29石。四、原佃户优先录用，不愿留者给田10亩、免税3年；不得驱逐，不得侵占民田、垄断水源。五、修渠、道路、粮仓及转运支银10万两，场长、农技、账房、审计支银4万两。六、皇庄向周边农户发良种并保底收购，不得强买强卖。七、净利六成入内库、三成再生产、一成发雇工奖金。八、逐庄公布亩数、产量、成交、成本和工资，库存不得冒充销售。

经此施行，高产作物形成可售粮540万石，传统粮作形成159万5000石，合计699万5000石，按每石8钱成交，营业收入559万6000两；种粮、农具、耕牛、工资、口粮、水利仓运及管理支出共300万两，净得259万6000两，按260万两计入本季考成。其中156万两入内库，78万两留作再生产，26万两发雇工奖金。皇庄稳定吸纳流民、无地农户及原佃户40万人，高产作物较旧制增加可售粮156万石，农民满意度提高2点，相关地区动乱风险下降2点。皇田、粮产、就业、内库和省级民心面板必须同步更新，缺一项即按未完成论。
```

# 十二、AI自检测试

生成政令后，必须逐项回答以下问题。

## 资源测试

- 资源总量是多少？
- 实际可用数量是多少？
- 不可用部分去了哪里？
- 是否出现全部资源直接投入、没有保留和损耗的错误？

## 产出测试

- 单位产出是多少？
- 单位产出的依据是什么？
- 总产出能否由乘法计算得到？
- 是否扣除留种、自用、废品和损耗？

## 收入测试

- 可销售数量是多少？
- 单价是多少？
- 总收入是否等于数量乘单价？
- 是否把库存、合同、在途或应收冒充收入？

## 成本测试

- 原料、工资、设备、运输、仓储、维修、管理是否齐全？
- 总成本能否由各项相加得到？
- 净收益是否等于总收入减总成本？

## 分配测试

- 各项分配比例是否合计100%？
- 每项金额能否由净收益乘比例得到？
- 是否存在同一笔银两重复分配？

## 面板测试

- 就业人数能否由工日计算？
- 满意度变化是否有真实受益基础？
- 军力变化是否有军械到营和训练支持？
- 建筑收益是否有实际使用率支持？
- 所有结果应更新哪些面板？

## 孤立数字测试

逐一检查政令结尾的每个数字：

> 能否在正文找到它的直接来源和计算过程？

不能找到来源的数字必须删除、补充依据或改为合理区间。

# 十三、禁止事项

禁止：

- 结尾突然出现没有计算过程的收入；
- 只写宏大方法，不写数量；
- 只写资源总量，不写实际投入量；
- 只写产量，不写损耗和商品量；
- 只写收入，不写成本；
- 把产能当产量；
- 把库存当销售；
- 把拨款当实际支出；
- 把开工当完工；
- 把毕业当到岗；
- 把武库拨出当军团列装；
- 同一收益重复进入不同项目；
- 所有政策同时提高收入、民心、权威、威望和军力；
- 使用“预计、有望、将逐步、待下季”代替最终结果；
- 在历史和状态数据库中把政策推演值提前记为已执行事实。

# 十四、输出原则

正式政令使用坚定、确定的皇帝口吻。

正文先证明资源和执行链，末尾统一结算结果。

对外诏书写：

```
经此施行，形成……达到……净得……
```

内部结构化数据必须分开保存：

```yaml
政策推演结果:
实际执行结果: null
执行状态: 待朝政纪要回填
```

下一季度收到朝政纪要后，才将实际结果写入历史和当前状态。

最终原则：

> 先证明资源确实存在，再证明资源如何被组织和投入，再证明投入如何形成产出，再证明产出如何成交或投入使用，再扣除全部成本，最后才允许写出明确收益。
