# 国策方案整理

## 目标

把玩家的制度想法整理为可密谈、可试行、可复核的国策设计，并严格区分计划、命令、结果和当前事实。默认只整理与写入档案；不开发或运行自动 Agent，不模拟游戏，不自动下诏，不自动替玩家决策。

## 开始前读取

从项目根目录依次读取：

1. `CURRENT_ARCHIVE.md`
2. `data/archive_manifest.json`
3. `data/latest_state.json`
4. `data/current_snapshot.json`
5. `data/current_directives.json`
6. `大明档案/00_总览/五层证据模型.md`
7. `大明档案/00_总览/战略项目台账.md`
8. `大明档案/00_总览/资料缺口与冲突清单.md`
9. `大明档案/03_国策与战略/01_制度规则/关键制度源头/01_长期国策有效清单.md`
10. `大明档案/03_国策与战略/01_制度规则/关键制度源头/02_季度试行与非永久政策清单.md`
11. `大明档案/03_国策与战略/02_战略方针/README.md`

13. 与议题相关的最新朝政纪要、诏书、国家专题档案和玩家笔记。

读取时以最新 L3 游戏反馈为事实源。旧 JSON、历史方案和玩家笔记只能补充背景；出现冲突时并列列出，不静默选择。

## 先判定资料去向

| 用户要整理的内容 | 写入位置 |
|---|---|
| 新长期国策、制度修订、废止或转正规则 | `大明档案/03_国策与战略/04_国策设计/` |
| 年度或多季度主攻方向、资源顺序与红线 | `大明档案/03_国策与战略/02_战略方针/` |
| 本季度负责人、额度、期限和验收任务 | `大明档案/01_季度政务/04_执行任务/` |
| 已经采用或执行过的历史专项方案 | `大明档案/03_国策与战略/03_已执行方案/` |
| 玩家教训、偏好或未成形想法 | `大明档案/03_国策与战略/05_玩家笔记/` |
| 已由玩家确认且有正式依据的长期制度 | 更新长期国策有效清单，并保留设计稿和证据链接 |

同一事项可以跨层链接，但不要复制成多个互相矛盾的“当前版本”。

## 整理新国策

1. 复制 `assets/国策方案模板.md`，在 `04_国策设计/` 直接建立 `GP-三位编号_国策名称.md`。
2. 查找现有文件的最大编号后顺延；不得复用已有编号。
3. 保留用户原意，先列“已知事实、玩家判断、待核问题”，不要擅自补造游戏数据。
4. 把政策拆为问题、制度机制、适用范围、权责、钱粮、监督、试行、验收、风险和退出机制。
5. 数值必须分别写实际基线、御前实得目标、预计执行系数、诏书底线、上考和失败线。没有可靠基线时标记“待核”，不要倒推假数。
6. 核对是否与当前长期国策、年度战略、在办诏令和当季任务冲突；冲突要列出来源和需要玩家决定的选项。
7. 若用户只要求整理，不起草密谈或诏书。若用户另行要求密谈或诏书，调用对应工作流并保留本方案链接。

## 更新状态

状态只按以下顺序推进：

`待整理 → 待密谈 → 试行设计 → 已下诏 → 待反馈 → 续试／转正／终止`

- 看到草稿或玩家想法，只能到“待整理”或“待密谈”。
- 找到正式诏书，最多到“已下诏／待反馈”；诏书不能证明执行完成。
- 只有季度纪要或游戏截图能登记 L3 实际结果。
- “转正”为长期国策必须同时满足：玩家明确确认、存在正式诏令或续行依据、存在可追溯反馈。随后更新长期国策有效清单。
- 终止或失败不删除文件；写明原因、结果、止损和是否可复用。

## 历史材料规则

`03_已执行方案/`中的文件已由玩家确认曾进入真实执行流程。不得再称为“未采用备选方案”。但其中目标、拨款、兵额和产量仍不能直接当作实际完成值；结果必须链接到季度纪要或截图。

移动或重命名历史资料时只改路径，不改正文，并核对 SHA-256。不要修改历史诏书、朝政纪要、国家事实档案或 `data/`，除非用户明确要求同步这些事实层。
