# writeimperial-causal-ledger

## 定位

把一项政令写成可计算、可验收、可在下一季度逐项回填的因果合同。坚持：

`资源基础 → 管理组织 → 生产方法 → 人员与投入 → 实际产出 → 销售或使用 → 成本扣除 → 收益分配 → 监督验收 → 最终面板结果`

确保政令末尾每一个收益数字都能逐级倒查到资源数量、单位产出、执行系数、合格率、损耗、价格和成本。删除或补足无法倒查的孤立数字。

## 与其他 Skill 的边界

| Skill | 职责 |
|---|---|
| `$writeimperial` | 读完整档案、判断季度主轴、使用 Scale v3.1 计算目标、组织密谈与四段诏书、等待反馈并更新资料 |
| `$writeimperial-compact` | 把已经成立的政策逻辑压缩为紧凑的四部分诏书或300至500字政令段落 |
| `$writeimperial-causal-ledger` | 为单项或多项量化项目建立资源—投入—产出—结算—验收的完整因果账本 |

组合使用时先由 `$writeimperial` 确定最新实际基线和合理目标，再用本 Skill 建账，最后按需要由 `$writeimperial-compact` 压缩表达。不得为了压缩删掉关键基线、成本、失败线或验收凭证。

## 先建立事实边界

把输入分为四类，禁止混写：

- **实际基线**：由最新 L3 游戏反馈或可追溯 L4 当前快照确认。
- **玩家命令**：正式诏书中的投入、责任、期限和目标，属于 L2。
- **政策推演结果**：按基线、Scale、转化率和成本推导的合同目标，不是事实。
- **实际执行结果**：下一季度朝政纪要或游戏截图确认后才能回填。

若关键基线缺失、来源冲突或算法无法成立，停止生成“确定收益”，改为输出缺口清单、公式和待核占位符。不得选择最乐观口径，不得虚构资源、价格、产能、人员或执行系数。

## 因果合同十道关口

逐项证明以下关口，任一关口缺失都不得直接宣布最终收益：

1. **存在**：资源、库存、土地、设备、人员或市场确实存在。
2. **可用**：扣除争议、保留、损坏、轮休、在途和不可调用部分。
3. **控制**：明确谁有权调拨、经营、生产、销售或列装。
4. **投入**：明确资金、原料、人工、设备、工日、运输和时间。
5. **转化**：说明生产方法、单位投入、单位产出和预计执行系数。
6. **合格**：扣除废品、损耗、留种、自用、维修和未验收部分。
7. **实现**：区分产出、入库、到营、实际使用、成交和实际到账。
8. **结算**：完整扣除成本，计算净收益或净军事效果。
9. **分配**：比例合计100%，同一资源和收益不得重复分配。
10. **验收**：指定原始凭证、复核机关、面板字段、底线、上考和失败线。

## 单项政令三段式

### 第一段：世界状态与项目总纲

写清资源总量、不可用量、实际可投入量、问题、归属机构、总负责人、协同机关、监察机关、资金来源和项目总目标。不得只写空泛背景。

### 第二段：编号执行链

使用三至九条编号，把同一项目写成不可分割的执行链。按项目需要覆盖：

1. 组织和管理；
2. 生产或行动布局；
3. 人员、工日和投入；
4. 原有人员和利益关系处理；
5. 地方权限、安全边界和停止线；
6. 技术、市场、运输和推广；
7. 销售、入库、列装和收益分配；
8. 账册、审计、证据和处罚。

每条尽量给出可计算数字和来源。多条共同形成一项最终结果，不要在每条重复结算整项收益。

### 第三段：统一结算

依次写实际投入规模、单位产出、毛产出、执行系数、合格率、损耗或留用、可销售或可使用量、单价或折算价值、总收入、全部成本、净收益、收益分配、附带效果、最终面板和验收凭证。

外部诏书可用坚定口吻写政策目标；内部账本必须明确标注其为“政策推演结果／待游戏反馈”。

## 强制定量账本

至少建立以下字段：

```text
资源总量
- 不可用、保留、争议、损坏和在途
= 实际可投入量

实际可投入量 × 单位产出 × 预计执行系数
= 毛产出

毛产出 × 合格率
- 留种、自用、损耗、废品和未验收
= 可销售、可入库、可列装或可使用量

可销售量 × 实际成交单价
= 总收入

总收入
- 原料 - 人工 - 设备 - 折旧维修 - 运输仓储
- 管理审计 - 护航损耗 - 奖励抚恤 - 其他成本
= 净收益

净收益 × 分配比例
= 各受益方金额，合计必须等于净收益
```

若是非营利项目，用“净效果”替代净收益，但仍计算投入、损耗、机会成本和可核成果。

## 与 Scale v3.1 对接

先区分并保留：实际基线、御前实得目标、预计执行系数、诏书底线、上考、失败线。不得使用统一“底线+30%、上考+50%”。

- 按 `$writeimperial` 的 A 至 L 任务类型选择增长和执行规则。
- 兵额、库存、固定赏银、常设机构等 J 类项目不得借因果账本任意放大。
- 满意度、威望、皇威、腐败和风险等 K 类结果必须同时提供可控领先指标和游戏实际结果层。
- 零泄密、零丢炮、补给不断等 L 类条件按阈值验收，不用普通增长率。
- 多条执行链共享同一资源时先做总额约束，再分配到各项目，防止一银多用、一兵多调。

## 成本最低覆盖

- 农业与皇庄：种子、农具、耕牛、工资、口粮、水利、道路、仓储、运输、管理、审计、损耗、留种和自用。
- 军工：原料、工匠、厂房设备、燃料、废品、返修、试射、配套弹药、运输和列装训练。
- 商贸与海贸：采购、包装、仓储、运输、护航、损耗、关税、佣金、坏账、退货和实际到账。
- 建设与物流：勘察、材料、劳工、征地、设备、运输、维护、季节停工、验收和投用率。
- 军事行动：兵员、粮饷、军械、马匹、行军、情报、伤亡、补充、战利品核验和战后守备。

出现其他项目时按同样原则补齐所有会消耗资源或降低转化率的环节。

## 非银两结果

- 就业人数由总工日除以人均工日计算，并把工资和口粮列入成本。
- 民心与满意度必须对应实际受益人口、到账工资、粮价、免税、安置或扰民变化。
- 动乱风险必须对应无业、粮价、赈济、土地纠纷、治安和军队扰民数据。
- 军力、经验和士气必须对应实到人员、训练、饷粮、军械到营、伤亡和核实战果。
- 建筑收益必须经过完工、验收、投用和利用率，不得把开工或完工直接当收益。

## 判断是否拆为独立政令

只有满足一项以上才拆分：负责人完全不同、使用独立专款、技术和产出独立、原项目不执行仍能成立、或结果进入不同核心面板。同一土地经营、生产、安置、销售和分配闭环不得拆成互相重复结算的小政令。

## 输出合同

按用户请求输出全部或部分内容：

1. **基线与证据表**：数值、季度、证据层级、来源、冲突。
2. **因果账本**：逐步公式、单位、执行系数、中间结果和成本。
3. **正式政令段落**：只有用户要求起草时才生成。
4. **验收合同**：责任人、部门、期限、凭证、面板、底线、上考、失败线和奖惩。
5. **内部状态**：

```yaml
政策推演结果: <按因果账本计算的目标>
实际执行结果: null
执行状态: 待朝政纪要回填
```

若用户只要求审计现有诏书，输出“成立／缺证／计算错误／重复计算／需玩家确认”清单，不擅自重写诏书。

## 完成前自检

- 资源总量、不可用量和实际投入量能否对上？
- 单位产出、执行系数、合格率和损耗是否有依据？
- 产出能否由公式复算？
- 是否区分库存、产量、入库、列装、成交和到账？
- 成本是否完整，净收益是否可复算？
- 分配比例是否为100%，是否重复使用资金、人员或产出？
- 非银两收益是否有受益人口、实物到位或实际战果支持？
- 每个末端数字能否回溯到直接来源？
- 政策推演是否与实际结果分栏？
- 是否指定下季度回填来源和失败处理？

任何一项失败，先修账或标记待核，不输出伪确定结论。
