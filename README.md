# 崇祯模拟器辅助管理系统

这是一个供个人使用的本地历史模拟游戏辅助工具，也可称为“崇祯皇帝私人政务档案管理系统”。

玩家把《历史模拟器：崇祯》每回合产生的信息录入本项目，由程序负责结构化保存、检索、归档和辅助分析。

## AI 读档导航

如果你是新的 AI 线程，接手本项目时请优先读取本节。这个仓库不是游戏模拟器，而是玩家长期经营《历史模拟器：崇祯》的档案库。你的任务通常是帮助玩家检索、整理、起草诏书或做局势复盘，不能自动操作游戏，不能替玩家自动执行决策。

推荐读取顺序：

1. 先读 `README.md` 或 `CURRENT_ARCHIVE.md`，确认项目边界和当前入口。
2. 读取 `data/archive_manifest.json`，确认当前档案版本、当前游戏时间和权威来源。
3. 读取 `data/current_snapshot.json`，取得本季度结构化事实与已知冲突。
4. 读取 `data/personnel_current.json` 和 `data/current_directives.json`，取得当前人事与下一季强制要求。
5. 读取 `大明档案/制度规则/崇祯模拟器诏书撰写长期记忆.md`，继承未完成、逾期和长期目标。
6. 再读 `大明档案/资料索引/上传资料目录.md`，了解玩家上传过哪些原始资料、对应时间节点和分类。
7. 按用户指定的游戏时间检索资料，例如“崇祯二年春”“崇祯十年春”；优先匹配 `游戏时间`、`时间节点`、文件名和 Markdown 标题。
8. 需要当前事实时，优先读取当前季度的朝政纪要和执行反馈；不得让旧 `game_state.json` 字段覆盖更新的纪要、诏书与快照。
9. 需要历史数组、批量统计或程序处理时，再读取旧 `data/` 固定 JSON，并应用当前快照覆盖。

核心资料位置：

- `data/current_snapshot.json`：当前季度结构化事实覆盖层，包含财政、军队、灾情、军工、人事、国策和口径冲突。
- `data/personnel_current.json`：当前季度六阁六部、专责任务与人事覆盖层。
- `data/current_directives.json`：当前执行判定、长期禁令和下一季度必须验收事项。
- `data/history_records.json`：结构化季度/回合历史记录，适合程序读取。
- `data/history/`：每季度独立的结构化执行记录。
- `data/personnel.json`：朝臣、武将、派系、职位、影响力、风险和关系历史档案。
- `data/edicts.json`：结构化诏书历史档案。
- `data/strategy.json` 与 `data/strategy/`：长期国策路线、季度草案和执行考成。
- `data/personal_notes.json`：玩家个人战略笔记、教训复盘、决策倾向；其中 `游戏时间` 字段用于定位这条想法对应哪个季度。
- `data/game_state.json`：国家态势历史底座，包括阶层、田税、海军、船种、党派、势力和地块。
- `data/archive_manifest.json`：当前档案版本、当前游戏时间、权威来源和已知口径冲突。
- `data/intelligence.json`：关键情报历史记录。
- `uploads/index.json`：上传文件元数据，包括分类、时间节点、备注、原始目录和哈希。
- `uploads/`：玩家上传的原始资料副本，通常只在需要核对原文时读取。

Markdown 知识库位置：

- `大明档案/皇帝日志/`：季度记录的人类可读版。
- `大明档案/朝政纪要/`：按年归档的朝政纪要和回合材料。
- `大明档案/朝臣档案/`：朝臣总档和季度人事复核。
- `大明档案/国家态势/`：全国态势、财政、军力、民心、动乱和军械资料。
- `大明档案/参谋笔记/`：玩家个人想法、战略教训、决策倾向。
- `大明档案/战略方略/`：阶段性战略方案、辽东/东江/内政等专题文稿。
- `大明档案/诏书全集/`：历次诏书原文与合集。
- `大明档案/战争记录/`：军事、战线和战事记录。
- `大明档案/财政报告/`：财政相关汇总。
- `大明档案/制度规则/`：诏书长期记忆、财政禁令和制度性规则。
- `大明档案/资料索引/`：上传资料目录，是查找外部资料的入口。

为玩家起草诏书或方案时：

- 必须先确认当前游戏时间，再按这个时间向前读取相关资料。
- 同一季度内，优先读取玩家最近录入的 `current_snapshot`、`current_directives`、长期记忆、`参谋笔记`、`国家态势`、`朝政纪要` 和上一轮 `诏书`。
- 涉及官员调度时，先读当前季度人事复核，再读 `personnel.json` 或 `大明档案/朝臣档案/朝臣总档.md`。
- 涉及钱粮、民心、动乱、军力、党派时，必须先读 `data/current_snapshot.json` 或当前季度 `大明档案/国家态势/`，再用旧 `game_state.json` 补历史背景。
- 涉及上传原始资料时，先读 `uploads/index.json` 或 `大明档案/资料索引/上传资料目录.md` 定位文件，再读取对应 `uploads/` 文件。
- 当前季度的最新朝政纪要、正式诏书和同回合面板截图是事实优先级最高的原始依据；当前快照是据此整理的结构化覆盖层，旧 JSON 是历史底座，Markdown 是便于阅读的知识库副本。
- 若旧 JSON 与更新的朝政纪要、诏书、截图或当前快照冲突，优先采用最新原始依据，并把冲突写入 `data/archive_manifest.json`，不得静默混用。
- 本季所列硬目标必须在季末逐项报告实际数、完成率、判定和证据；无实际数按未完成。

## 网页版资料管理

网页版与命令行版共用同一套 JSON 数据和 Markdown 知识库。它负责资料录入、个人想法收录、上传、下载和同步，不直接操作游戏。

最方便的启动方式是双击：

```text
启动网页版.cmd
```

也可以在 PowerShell 中运行：

```powershell
cd "E:\AIS\AI任务执行清单\0730\崇祯模拟器辅助管理系统"
py -3 web_app.py --open
```

启动后访问：

```text
http://127.0.0.1:8765
```

网页版支持：

- 新增季度、朝臣、诏书、国策和情报档案。
- 一次性粘贴个人战略笔记、教训复盘和决策倾向。
- 保存游戏截图识别出的国家态势表，包括阶层、田税、海军、船种、党派、势力和地块。
- 搜索并修改已有记录。
- 按档案类型导出 JSON。
- 同步“大明档案”Markdown 知识库。
- 一次选择多个 JSON、Markdown、文本、CSV、PDF、Word、Excel 或图片。
- 根据文件名自动分类并识别朝代、年份和季节时间节点。
- 自动分类包括诏书资料、天下大势、朝政奏报、战争资料、财政资料、人物资料和回合导出。
- 使用 SHA-256 哈希避免同一文件被重复收录。
- 下载已经上传的原始文件。

上传文件原样保存在 `uploads` 目录，单个文件最大 10MB。网页后端不会读取或分析其内容。

个人想法保存在 `data/personal_notes.json`，并同步到
`大明档案/参谋笔记/个人战略笔记.md`。录入时需要手动填写当前游戏时间，例如“崇祯二年春”，正文仍然只需一次性粘贴整段内容，后续 AI 起草诏书时会按游戏季度读取并自行解析。

上传元数据保存在 `uploads/index.json`，并生成便于查看的
`大明档案/资料索引/上传资料目录.md`。上传文件会标记为“诏书参考”，时间节点也可以在上传前由用户手动指定。

为保护本地资料，网页服务只允许绑定 `127.0.0.1` 或 `localhost`，不会开放给局域网和互联网。

## Markdown 知识库模式

程序默认启用 Markdown 知识库。启动程序或修改档案后，会把 JSON 快照同步到 `大明档案`。

- JSON 是结构化数据源，适合程序读取。
- Markdown 是阅读副本，适合长期浏览、搜索和整理。
- AI 分析报告会按生成时间单独保存，不覆盖旧报告。
- 建议通过命令行菜单修改数据，再同步 Markdown；不要把 Markdown 当成反向导入源。

如需修改设置，把 `config/config.example.json` 复制为 `config/config.json`，可配置：

```json
{
  "markdown_knowledge_base": true,
  "knowledge_base_directory": "大明档案",
  "analysis_recent_turns": 6
}
```

## AI 辅助分析逻辑

分析模块读取季度记录、人物、诏书、长期国策和关键情报，生成：

- 当前局势：财政、军事、民生、朝堂。
- 长期目标：当前方向、需要坚持、需要调整。
- 风险提醒：人物风险、受阻诏书、高等级情报。
- 建议：补录、核实和复盘的优先事项。

当档案证据不足时，系统会明确显示“现有档案不足”，不会编造历史事实。所有建议只供玩家参考。
