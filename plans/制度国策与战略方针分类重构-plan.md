## Requirements Summary

### Problem Statement

当前 `制度规则`、`年度国策`、`战略方略`、`国策路线` 和 `季度目标` 同时包含长期制度、跨季目标、当季试行、执行原稿与 AI 规则。文件名中的“国策”无法说明有效期，导致当季指标可能被误读为永久国策，战略方针又与国策重复。

### Scope

- 建立五类定义：长期国策、战略方针、战略方略、季度试行、AI/档案规则。
- 将关键制度原稿集中到 `制度规则/关键制度源头/`，只移动与重命名，不改原文。
- 将原 `年度国策/` 改为 `战略方针/`，按年度跨季、已批准项目、历史计划复核分流。
- 保留 `国策路线/` 作为旧 JSON 的历史兼容镜像，不再作为长期国策入口。
- 更新 README、总控入口、AI 起草读取路径和迁移记录。
- 不修改诏书正文、朝政纪要正文、当前国家数值和历史结果。

### Success Criteria

- [ ] 每个长期制度能追溯到原稿、正式诏书和游戏反馈。
- [ ] 当季试行和一次性预算不会出现在“当前长期国策”中。
- [ ] 原制度文件移动后 SHA-256 不变。
- [ ] 旧路径引用全部更新或在迁移记录中可追溯。
- [ ] Markdown 链接、JSON 和 Python 语法检查通过。

### Constraints

- 历史原文不改写、不删除。
- “已经下令”不等于“已经完成”；当前事实仍只由 L3 结果更新。
- 12年春诏书尚未披露，不得补造当前命令。

### Assumptions

- 用户所说“改一改”授权本次分类、重命名和路径迁移，但不包含 Git 提交、推送或 PR。
- 同步前27份本地独有资料仍按玩家确认的真实计划／规则原稿保护。

## Architecture

### Five-category model

1. **长期国策／制度**：已由诏书确立或后续回执确认，跨季继续，直至明令废止。
2. **战略方针**：一年或多季的方向、优先级与资源边界；到期后进入历史，不自动延续。
3. **战略方略**：为实现方针提出的专项打法或备选路线；只有转入正式诏书才成为命令。
4. **季度试行**：限定地区、季度、额度或试验对象；期满必须复核、续期、固化或终止。
5. **AI／档案规则**：约束资料读取和诏书起草，不属于游戏内国策。

## Implementation Plan

1. 计算待迁移原文件哈希，建立旧路径清单。
2. 用 `git mv` 集中关键制度原稿并规范文件名。
3. 将原 `年度国策` 内容分流到 `战略方针` 三个子目录。
4. 编写制度谱系、长期有效清单和季度试行清单。
5. 重写目录 README 与总控资料地图，更新 AGENTS、manifest 和 writeimperial 读取路径。
6. 更新项目代码中“国策路线”标签，明确其为历史策略镜像。
7. 全仓搜索旧路径，修复有效引用；保留历史迁移记录中的旧路径。
8. 验证 SHA-256、JSON、Python、Markdown 链接和 Git diff。
